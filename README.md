# KRAS Quick

Windows용 부동산종합증명서 조회·저장 도구입니다. 버전 3.0.0부터 Rust 런타임을 사용합니다.

실사이트 전체 기능 검증은 완료되지 않았습니다. 접속 차단·보안문자 반복 실패가 발생하면 실행을 중단하고 서비스 운영기관의 안내를 따르세요.

```text
npx kras-quick
```

Windows x64와 Node.js 18 이상이 필요합니다. Node.js 없이 사용하려면 [3.0.2 릴리스](https://github.com/HaYanJongSeong/kras-quick/releases/tag/v3.0.2)의 EXE를 사용하세요. 최초 실행 시 OCR 모델 런타임을 GitHub에서 준비합니다.

변경사항과 검증 범위는 아래에 정리했습니다. 저장소의 이전 설치 스크립트는 3.0.x용으로 검증하지 않았습니다.

## 산출물

직접 실행하면 EXE 폴더에 저장합니다. npx는 `%USERPROFILE%\Downloads\kras-quick.exe`를 설치·실행하고, `%USERPROFILE%\Downloads\KRAS\지번\`에 저장합니다. 기존 업무자료는 이동·삭제하지 않습니다. Windows에서 다운로드 폴더를 다른 위치로 변경한 경우에도 현재 설치기는 위 고정 경로를 사용합니다.

```text
KRAS/
├─ 작업로그_20261118_153045.jsonl
└─ 지번/
   ├─ 지번-건물명.pdf
   └─ 기타/
      ├─ 지번-건물명.xml
      ├─ 지번-건물명.json
      └─ 작업로그.jsonl
```

토지는 건물명 없이, 층호 문서는 층호까지 파일명에 표기합니다. 정상 산출물이 확인되면 중복 출력은 건너뜁니다.

XML은 OZ 원문입니다. 같은 이름의 JSON은 `document`에 전체 태그·속성·계층·반복 항목·빈 값·문자열을 보존하고, `summary`에 주요 항목을 따로 둡니다. PDF에 사용한 PNG는 별도로 저장하지 않습니다.

대화형 실행의 전체 진행·오류 로그는 상위 `KRAS` 폴더에 실행별로 저장합니다. 파일명은 마지막 처리 종료 시각의 한국시간 연월일·시분초이며, 같은 이름이 있으면 `_2`, `_3`을 붙입니다. 비정상 종료 시에는 `작업로그_진행중_…jsonl`이 남습니다. 필지별 `기타/작업로그.jsonl`은 단계·산출물 무결성 확인용 기록이며, 기존 기록은 옮기거나 삭제하지 않습니다.

## 변경사항

### 3.0.2 · 오류 복구와 메모리 사용 개선

- 일시적인 사이트 처리 오류는 실패로 기록하고 남은 주소를 계속 처리합니다. 접속 차단·사용자 취소·분류할 수 없는 오류는 목록을 보존하고 멈춥니다.
- 로그인 만료 시 현재 주소와 남은 목록을 유지합니다. 재로그인을 확인한 뒤 같은 주소부터 이어갑니다. 미처리·실패 목록은 파일로 보관하며, 시작할 때 자동으로 불러오거나 실행하지 않습니다.
- 여러 줄 입력에서 메뉴 명령과 주소·범위 선택이 섞여 소비되던 문제를 고쳤습니다. 층호의 순서가 바뀌어도 식별값으로 다시 찾고, 사라진 층호 대신 다른 문서를 저장하지 않습니다.
- 전체 작업 로그를 마지막 필지 폴더가 아닌 상위 `KRAS` 폴더에 실행별로 저장합니다.
- PNG 버퍼의 중복 복사를 줄이고, PDF에 옮겨 담은 압축 버퍼는 차례로 해제합니다. 최신 단계 기록을 찾을 때 모든 행을 파싱해 모으던 작업도 줄였습니다. 이미지 해상도·PDF 압축 수준·원문 보존·무결성 검사는 유지합니다.
- 실행 파일 빌드에 thin LTO를 적용했습니다. 개발 PC의 합성 자료 비교에서는 EXE 크기와 처리 프로세스의 최대 작업 메모리가 줄었고, 생성 PDF의 바이트가 동일했습니다. 이 결과를 실사이트 전체 속도 향상으로 보장하지는 않습니다.

### 3.0.0 · Rust 전환

실행 본체를 Rust로 옮기고 Python OCR 워커를 제거했습니다. `npx kras-quick`은 그대로 쓰며, Node.js는 EXE를 실행하는 역할만 맡습니다.

저장 파일도 정리했습니다. PDF와 원문 XML에 전체 정보 JSON을 더했고, 단계별 기록은 `작업로그.jsonl` 하나로 합쳤습니다. JSON에는 XML의 태그·속성·계층·반복 항목·빈 값과 문자열을 보존합니다. PDF를 만들 때 쓴 PNG는 따로 저장하지 않습니다.

### 3.0.1 · 아이콘과 오류 수정

EXE와 GitHub·npm 문서는 남색 바탕에 흰 종이비행기와 파란 `+`가 들어간 아이콘을 사용합니다. 아이콘은 3.0.0부터 적용돼 있습니다.

- `npx kras-quick` 실행 시 EXE를 다운로드 폴더에 설치하고, 같은 폴더의 `KRAS`에 결과를 저장하도록 고쳤습니다. 기존 자료는 옮기거나 삭제하지 않습니다.
- 처리 실패나 보안문자 입력 취소·EOF·접속 차단이 발생하면 배치를 멈춥니다. 미처리 주소는 현재 실행 중인 프로그램의 대기 목록에 남기며, 모드를 바꿔도 지우지 않습니다.
- 동시에 저장하더라도 기존 PDF·XML·JSON을 덮어쓰지 않도록 수정했습니다. 손상된 JSON을 이전 형식의 검증 결과로 건너뛰던 문제도 고쳤습니다.
- 입력이 끝났을 때 전체 처리가 자동으로 시작되는 문제를 막았습니다.

### 확인한 범위

3.0.2는 Windows의 일반·최적화 빌드에서 각각 Rust 테스트 460개가 통과했습니다. 설치기 검사와 접속 차단·사이트 오류 안내 검사, EXE 빌드·버전 실행도 확인했습니다. 기본 검사에서 제외한 10개 중 합성 벤치마크 2개는 별도로 실행했고, 나머지 8개는 이번 검증에 포함하지 않았습니다. 로그인 만료 후 재개와 일반 오류 후 다음 주소 진행은 사용자의 실사이트 확인을 받았지만, 실사이트 전체 기능을 새로 검증한 것은 아닙니다.

저장 도중 오류가 나면 일부 새 파일이 남아 재실행이 중단될 수 있습니다. 기존 PDF·XML·JSON을 덮어쓰지 않기 위한 동작이며, 자동 삭제하지 않습니다. 접속 차단이 발생하면 조회를 계속하지 말고 서비스 운영기관의 안내를 따르세요.

아래는 이전 3.0.1의 검사 결과입니다.

3.0.1은 Rust 테스트 419개, 설치기 테스트 5개와 접속 차단 안내 3종 검사를 통과했습니다. Windows EXE 빌드와 로컬 npm 설치·버전 실행도 확인했습니다. 별도 조건이 필요한 테스트 8개는 제외했으며, 실사이트 전체 기능과 속도는 아직 검증하지 않았습니다.

## 아이콘

앱·문서·패키지는 남색 바탕의 흰 종이비행기와 파란 `+` 아이콘으로 통일합니다.
일사편리 파비콘을 참고한 별도 도구용 아이콘이며, 정부 공식 앱을 뜻하지 않습니다.

## 개발

Rust 소스는 `rust/`에 있습니다. Windows SDK의 리소스 컴파일러가 필요합니다.

```powershell
cargo test --manifest-path rust/Cargo.toml --locked
cargo build --manifest-path rust/Cargo.toml --release --locked
```

실사이트 테스트는 기본 실행에서 제외합니다. [MIT 라이선스](LICENSE)를 따릅니다.
